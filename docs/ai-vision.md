# AI 识别配置与使用指南

本文说明 Baby Tracker「拍照识别与批量录入」功能的工作流程、AI 服务配置、可识别字段、隐私注意事项与常见问题；本功能的核心是 **AI 只产候选记录、绝不直接写库，所有记录必须经总览确认后一次性录入**。

## 工作流程

1. **拍照 / 选图**：在总览页入口拍照，或从相册选择已有图片。
2. **前端压缩**：浏览器用 Canvas 将图片压缩到最长边 1600px、JPEG 质量 0.8，减少上传体积。
3. **AI 识别**：后端调用 OpenAI 兼容的 `/chat/completions` 视觉模型，对图片做通用记录提取。
4. **候选记录（不入库）**：AI 返回结构化候选记录，覆盖 `feed`（喂养，含辅食子类型）、`excrete`（排泄）、`symptom`（症状）、`supplement`（补充，如维D/铁剂/钙剂）四类；**此时不写入数据库**。
5. **总览确认**：所有候选进入「总览确认」弹窗，可逐行核对、编辑、勾选、删除；支持多张照片累积候选，也支持手动添加行。顶部实时汇总「共 N 条 / 将录入 X 条 / 喂养合计 Y ml」。
6. **一次性提交**：确认后调用 `POST /api/records/batch`，在单个事务中写入全部勾选记录；失败整批回滚，并写入一条操作日志。
7. **刷新总览**：录入成功后刷新总览数据，查看最新统计与记录明细。

文字流程图：

```text
拍照/选图 → 前端压缩 → AI 识别 → 候选记录（不入库）
   → 总览确认（核对 / 编辑 / 勾选 / 删除 / 多图累积 / 手动加行）
   → 一次性提交 POST /api/records/batch（单事务）→ 刷新总览
```

> 批量录入不依赖 AI：即使未配置或无法使用 AI，也可在总览确认弹窗中纯手动添加行后提交。入口在总览页，所有已登录（approved）用户可用。

## 配置

配置可在 **管理页「AI 识别配置」卡片** 中设置 `base_url` / `model` / `max_tokens` / `api_key`，也可通过环境变量设置：

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `AI_VISION_BASE_URL` | `https://api.openai.com/v1` | OpenAI 兼容接口地址 |
| `AI_VISION_API_KEY` | 空 | 服务商 API Key |
| `AI_VISION_MODEL` | `gpt-4o-mini` | 视觉模型名 |
| `AI_VISION_MAX_TOKENS` | 不设置 | 单次响应最大输出 token；默认不下发，由服务商/模型决定（显式设置范围 256~32768） |
| `AI_VISION_TIMEOUT` | 不设置 | 单次请求超时秒数；默认不限时，避免长耗时识别被提前中断 |

> **默认不限制**：`max_tokens` 与超时都不主动下发。这样模型可以按自身默认上限完整输出，长耗时识别也不会被提前掐断；代价是极端情况下请求可能占用较久（可用 `AI_VISION_TIMEOUT` 自行加保护）。

- **优先级**：环境变量 > 管理页配置。设置了环境变量时，管理页对应值不会生效。
- **密钥回显**：管理页读取配置时只显示掩码，不回显完整 API Key；JSON 备份导出会过滤掉 API Key。
- 切换服务商只需改 `base_url` 和 `model`（必要时换 `api_key`），无需改动代码。

### 服务商示例（OpenAI 兼容模式）

| 服务商 | `base_url` | `model` 示例 | 备注 |
| --- | --- | --- | --- |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` / `gpt-4o` | 默认配置 |
| 阿里云通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-vl-max` / `qwen-vl-plus` | 使用 DashScope 兼容模式 |
| 智谱 | `https://open.bigmodel.cn/api/paas/v4` | `glm-4v-flash` / `glm-4.5v` | 使用智谱兼容接口 |
| 本地 Ollama | `http://<宿主机IP>:11434/v1` | `qwen2.5vl` / `llava` | 需设置 `OLLAMA_HOST` 允许局域网访问；`api_key` 可填任意非空值 |

> 以上均为 OpenAI 兼容模式示例，实际可用的模型名、参数与计费以各服务商官方文档为准。

## 识别范围与字段映射

### 支持的图片

- 格式：`jpeg` / `png` / `webp`。
- 大小：单张不超过 10MB；上传前前端会压缩（最长边 1600px、JPEG 0.8）。

### 可抽取的记录类型

识别为「通用记录提取」：手写记录本、其他 App 截图、奶瓶 / 尿布实物照等，都会尝试抽取成多条候选记录，共四类：

| 类型 | 含义 |
| --- | --- |
| `feed` | 喂养（配方奶、母乳、喂水，以及 `solid_food` 辅食等子类型） |
| `excrete` | 排泄（排尿、排便等） |
| `symptom` | 症状（体温、异常表现等） |
| `supplement` | 补充（维D、维AD、铁剂、钙剂、DHA、益生菌等营养补充剂） |

> 注意：「辅食」属于 `feed` 类型的 `solid_food` 子类型（计量单位可为 g / 勺 / 块），与 `supplement`（营养补充剂）是不同概念。

### 字段

每条候选可包含：类型、子类型、量、时长、颜色、性状、体温、备注、**日期**、时间、辅食单位。不同类型按需填写对应字段，未识别到的字段留空，由用户在总览确认时补齐。

### 日期与时间处理规则

**日期**：

- 图片中能清晰读到日期（如记录本抬头、表头、截图上的日期）时，AI 会一并返回该日期，**优先采用图片日期**，并在总览页该行的「日期」字段标注「· 图片」、给出「已采用图片中的日期」提示（仅提示，不影响该行有效性）。
- 支持 `YYYY-MM-DD`、`YYYY/MM/DD`、`MM-DD`、`MM/DD` 及中文「11月8日」；只有月日时年份取当前所选「录入日期」的年份。
- **读不到日期或日期不合法时不处理**：完全沿用弹窗中所选的「录入日期」，不做任何猜测或填补，也不会产生提示。
- 修改弹窗顶部的「录入日期」时，仅同步未标注「· 图片」的行；已识别到图片日期的行保留原值（仍可逐行手动改，手动改后即视为普通行）。
- 若 AI 直接返回了完整时间戳（`YYYY-MM-DD HH:MM:SS`），则以该时间戳的日期为准。

**时间**：

- 图片中只有 `HH:MM` 时：按上述确定的日期补全为完整时间。
- 完全没有时间信息时：使用当前时间，并给出「时间未识别，已用当前时间」警告。
- 已有完整日期时间的记录按原值保留。

### 置信度与警告

- 每条候选带置信度与文字警告，例如「时间未识别，已用当前时间」「识别置信度较低，请核对」。
- 低置信度行在总览确认界面**标黄**提醒，请优先核对这些行。
- 置信度仅作参考，**最终以人工在总览页核对为准**：任何行都可编辑、取消勾选或删除。

## 隐私与数据安全

- 使用第三方 AI 服务时，待识别的图片会**发送给所配置的服务商**，请勿上传含有敏感信息的照片。
- API Key 保存在 settings 表中，管理页 GET 配置只显示掩码、不回显完整值；**JSON 备份导出会过滤掉 API Key**，密钥不会随备份外泄。
- 建议通过 HTTPS 访问，并尽量在内网或可信网络中部署；不要把服务直接暴露到公网（呼应 [README.md](../README.md) 的「运维与安全」章节）。
- 隐私敏感场景建议改用**本地 Ollama**，图片不出内网；此时 `api_key` 可填任意非空占位值。
- 批量录入本身不依赖 AI，可完全离线、纯手动使用。

## 日志与排查

识别相关的调用与返回都会写入日志，用于定位「识别失败」「结果不准」「返回非 JSON」等问题。

**看日志的两种方式**

1. **管理页**（推荐，手机也能看）：管理 → 「AI 识别日志」卡片 → 选择行数 → 「刷新」。
2. **命令行**：

```bash
docker logs --tail 200 baby_tracker          # 容器标准输出
tail -n 200 ./data/ai_vision.log             # 持久化日志文件（随 data 卷）
```

**日志记录了什么**

| 阶段 | 内容 |
| --- | --- |
| 请求 | 接口地址、模型名、超时、是否带图片；识别接口还会记录用户、日期、图片字节数 |
| 响应 | HTTP 状态码、耗时（ms）、响应字节数、上游 `request_id`（若返回） |
| 原始内容 | 模型返回的完整文本（默认记录，超过 `AI_VISION_LOG_MAX_CHARS` 会截断） |
| 解析结果 | 共识别几条、有效几条；每条的 type / sub_type / amount / 时间 / 告警与错误 |
| 失败 | HTTP 错误码与上游错误体、网络错误原因、超时、非 JSON 返回、未知异常堆栈 |

**不会记录**：图片本身、API Key（日志中对密钥做脱敏）。

**相关环境变量**

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `AI_VISION_LOG_LEVEL` | `INFO` | 日志级别；排查时可设 `DEBUG` |
| `AI_VISION_LOG_RAW` | `1` | 设为 `0` 关闭「原始返回内容」，只保留摘要（隐私更保守） |
| `AI_VISION_LOG_MAX_CHARS` | `4000` | 单条原始内容的最大字符数 |

日志文件 `data/ai_vision.log` 采用滚动策略（5MB × 3 份），不会无限增长；已被 Git 忽略，不会进入备份。

## 常见问题

**未配置 AI 时拍照提示什么？**
未填写 `api_key` 或配置不完整时，识别接口会返回未配置提示，不影响其它功能；可先到管理页「AI 识别配置」填写，或改用纯手动批量录入。

**为什么总是「返回内容不是有效 JSON」，日志里 finish_reason=length？**
这是**输出被 max_tokens 截断**：一张图里记录太多时，模型输出的 JSON 还没写完就到了上限。处理方式：
1. 把「最大输出 token」调大：管理页「AI 识别配置」→ max_tokens（默认留空即不限制；填写范围 256~32768），或用环境变量 `AI_VISION_MAX_TOKENS`（环境变量优先）；
2. 或把记录密集的一页拆成多张照片分批识别；
3. 也可换输出上限更高的模型。
日志中会明确记录 `finish_reason=length` 与实际 `completion_tokens`，便于确认。

**请求超时 / 识别很慢怎么办？**
视觉模型推理可能较慢。Docker 镜像的 Gunicorn 已调整为 2 workers、timeout 120s；网络不通或模型响应过慢时会超时，可检查 `base_url` 连通性、更换更快的模型（如 `gpt-4o-mini` / `glm-4v-flash`），或改用本地 Ollama。

**AI 返回非 JSON 或识别不准怎么办？**
识别结果解析失败时不会写入任何记录，可重试或换模型。AI 结果只作候选，**以总览页人工核对为准**：逐行编辑、取消勾选或删除错误行，再统一提交；不必依赖 AI 一次识别准确。

**离线 / PWA 下还能用吗？**
PWA 离线缓存了页面资源，但 AI 识别需要访问所配置的服务端，离线时不可用；不过**手动批量录入仍可正常使用**（候选行由用户手动添加，联网后再提交）。
